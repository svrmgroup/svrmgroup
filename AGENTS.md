# Project rules
- Remote assistant tools live in src/lib/mcp, require verified OAuth client tokens and the existing admin role, and use caller-scoped SELECT queries only; this preserves RLS and avoids privileged or public access.
- MCP invoices expose stored booking invoice data, not browser-only PDF edits; financial summaries use the existing P&L accounting basis and reject truncated results.
- OAuth consent reuses admin sign-in and validates local return paths once; keep both sign-in and signup return URLs intact.
- Vehicle galleries are optional vehicle data and use the shared carousel; ordinary fleet cards retain their existing image presentation.
- Persist CDN image URLs in CMS seed data only when stable; never persist build-hashed import URLs.
- Keep FAQ answers in typed data with shared contact enrichment and rendering; generate FAQ schema from the same answers so visible content and search data cannot diverge.
- Main public routes get static head + summary HTML at build via `src/seo/prerenderRoutes.ts` and the Vite plugin; keep that table in sync with each page's `<Seo>` so non-JS crawlers see the same metadata.
- Business contact constants live in `src/lib/whatsapp.ts`; reuse them instead of re-typing contact details.
- Cancellation tiers and FAQ/document terms share `src/lib/cancellationPolicy.ts`; invoices, confirmation PDFs and freshly generated admin confirmation messages consume it so terms cannot drift. Keep thank-you PDFs unchanged.
- Google Ads loading and conversions go through `src/lib/adsConsent.ts` (regional consent banner route, both Ads accounts); never add static Ads tags to index.html.
- Customer phone controls merge caller classes with explicit country/number sizing and wrap in narrow containers; admin grids use shrinkable tracks and scoped field sizing so entered details remain visible.
- Admin notification panels use the shared portalled, collision-aware Popover with viewport-constrained height and a scrolling list so sidebar and mobile triggers cannot push alerts off-screen.
- Keep Organization and WebSite brand aliases consistent in static head and homepage JSON-LD so crawlers and client rendering identify the same business.
- Surface tokens (`surface-deep`, `surface-raised`) are registered in `tailwind.config.ts` with `<alpha-value>`; without registration their opacity and gradient utilities (`bg-surface-deep/70`, `from-surface-deep`) silently render nothing — keep new tokens registered there rather than as bare CSS classes.
