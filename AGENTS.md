# Project rules
- Display media through shared responsive-image renditions and adaptive background-video sources; retain original URLs for CMS, image search and explicit full-size viewing so speed improvements cannot replace masters or alter business content.
- Prefer HD background-video renditions on normal connections, including phones; reserve smaller copies for constrained networks to avoid unnecessary softness without downloading heavy masters.
- Remote assistant tools live in src/lib/mcp and require verified OAuth client tokens and the existing admin role; create/update tools additionally require per-user/client management consent and a token issued after consent, preserving RLS and prior read-only grants.
- Assistant writes use strict field allowlists and optimistic concurrency for bookings/invoices, clients and expenses; never expose deletion, messaging, payment execution, role changes or website publishing.
- MCP invoices expose stored booking invoice data, not browser-only PDF edits; financial summaries use the existing P&L accounting basis and reject truncated results.
- OAuth consent reuses admin sign-in and validates local return paths once; keep both sign-in and signup return URLs intact.
- Vehicle galleries are optional vehicle data and use the shared carousel on chauffeur and rental cards, with uncropped expanded viewing; ordinary fleet cards retain their existing image presentation.
- Persist CDN image URLs in CMS seed data only when stable; never persist build-hashed import URLs.
- Vehicle seed images include stable asset-pointer URLs even without galleries, so CMS resync preserves refreshed fleet photos.
- Keep FAQ answers in typed data with shared contact enrichment and rendering; generate FAQ schema from the same answers so visible content and search data cannot diverge.
- Main public routes get static head + summary HTML at build via `src/seo/prerenderRoutes.ts` and the Vite plugin; keep that table in sync with each page's `<Seo>` so non-JS crawlers see the same metadata.
- Vehicle chauffeur descriptions, flagship slug, keyword generation and service offers share `src/seo/vehicleServices.ts`; fleet data, CMS seeds and static summaries reuse these to keep vehicle positioning aligned.
- Refreshed fleet image discovery lives in `src/seo/vehicleImages.ts`; keep its stable pointers and self-drive eligibility aligned with vehicle photos so static service HTML and image sitemap reference the displayed fleet.
- Business contact constants live in `src/lib/whatsapp.ts`; reuse them instead of re-typing contact details.
- Cancellation tiers and FAQ/document terms share `src/lib/cancellationPolicy.ts`; invoices, confirmation PDFs and freshly generated admin confirmation messages consume it so terms cannot drift. Keep thank-you PDFs unchanged.
- Google Ads loading and conversions go through `src/lib/adsConsent.ts` (regional consent banner route, both Ads accounts); never add static Ads tags to index.html.
- Customer phone controls merge caller classes with explicit country/number sizing and wrap in narrow containers; admin grids use shrinkable tracks and scoped field sizing so entered details remain visible.
- Admin notification panels use the shared portalled, collision-aware Popover with viewport-constrained height and a scrolling list so sidebar and mobile triggers cannot push alerts off-screen.
- Keep Organization and WebSite brand aliases consistent in static head and homepage JSON-LD so crawlers and client rendering identify the same business.
- Surface tokens (`surface-deep`, `surface-raised`) are registered in `tailwind.config.ts` with `<alpha-value>`; without registration their opacity and gradient utilities (`bg-surface-deep/70`, `from-surface-deep`) silently render nothing — keep new tokens registered there rather than as bare CSS classes.
- Enquiry references, per-service WhatsApp prefills, consent-gated ad attribution and the Google Ads import sheet live in `src/lib/enquiryTracking.ts`; every enquiry insert spreads `trackingFields()` and a `newReference()` so ads can be judged on booked contribution, not taps.
- Enquiry stage, money and flags are set only by admins: the `enquiries_prepare` trigger resets them for public inserts and drops click IDs without ad consent; import-sheet conversion names must match the Google Ads upload actions exactly.
- Supplier/partner applications never report the Website Enquiry conversion, so guest-lead counts stay clean.
- Listing detail pages (`/chauffeur/:slug`, `/rentals/:slug`, `/stays/:slug`, tours) derive content from `src/data/listings.ts`; unknown figures say "Your concierge will confirm" so nothing unverified is presented as fact.
- After changing vehicles or stays, run `bun scripts/generate-listing-routes.ts` to refresh static heads and the sitemap; `src/seo/listingRoutes.test.ts` fails when they drift.
- Item-aware WhatsApp enquiries are built in `src/lib/listingEnquiry.ts` (tested); links carry `data-wa-source` so the global tracker logs them once — never log message contents.
- Admin listing photos live in `listing_photos` + private `listing-photos` bucket (public read via signed URLs, admin-only writes); they show before existing site photos and never replace them.
